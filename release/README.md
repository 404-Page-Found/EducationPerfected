# Phase 3 release evidence

The [Publish workflow](../.github/workflows/publish.yml) builds, verifies and attaches the release files to an existing release (used for v2026.11.16); it never creates tags, edits or publishes the release itself. `npm run build:linux-dev` and `npm run build:windows-dev` are local development builds, not releases. The selected unsigned direct-download policy does not prove native launch readiness. `npm run release:check` is a fail-closed evidence checklist, not an upload command or permission to publish.

Create an untracked `release/evidence.json` from the example only after evidence is reviewed. Every global and per-target check must be `passed`, name the exact current source commit, link its evidence and name its reviewer. A skipped Windows child-signal fixture, another platform's result or package availability is not native proof. The validator checks completeness and freshness, not evidence authenticity or legal clearance. A future release workflow must invoke this check before any artifact publication, and still require owner authority.

Native lanes selected by the owner: Windows x64, macOS ARM64, macOS x64, Linux x64, Linux ARM64. Development builder source exists for native glibc Linux x64/ARM64, Windows x64 and macOS ARM64/x64. Native Mac ARM64/Intel development builds, ad-hoc signatures, packaged local browser and isolated synthetic source CRUD/packaged setup-health-read-delete passed. Windows source-worker synthetic CRUD and SEA setup/source-exact-pair/health-read/delete passed, along with both empty-input cancellations and raw byte3 interruption at both setup prompts without mutation. SEA health proves shape, not returned exact values; raw byte3 proves input handling, not OS console events. Browser reliability, normal saved-login use on the unmodified production artifact, locked/unavailable-store behavior and real console/no-Node checks remain unproved. Separate Linux x64/ARM64 build-time-modified loopback fixture normal saved-login observations passed; they are not production-artifact or release evidence. See the November3 observations in `native-validation.md`. Linux x64/ARM64 private-store and packaged development matrices passed. These are bounded development results, not full release attestations; exact Mac packaged values and normal sign-in use remain open. See `native-validation.md` for the checkpoint URLs and scope. All lanes still need complete release evidence, including signing-compatible payload verification and native hosts. For each lane verify: no-Node fresh machine launch, extracted browser path, native credential save/read/delete, safe console shutdown, packaging integrity and the selected signing/unsigned policy. Windows needs actual console events, not child.kill emulation. No paid runners or certificates are approved by this checklist.

Global gates: project contribution rights, browser redistribution, dependency notice completeness and artifact integrity. Source licenses recovered from exact npm gitHead are recorded under `packaging/notices/provenance.json`; copying license texts does not settle all legal obligations or project rights. Browser files and native binary third-party notices also need review.

The checkout must be clean, including source hidden by local/global Git excludes. Only generated `node_modules/`, `build/` and `release/evidence.json` are allowed as untracked paths. Git environment overrides are removed and Git is invoked only at `/usr/bin/git` (Linux/macOS) or `C:\Program Files\Git\cmd\git.exe` (Windows). Nonstandard installations fail closed; this does not certify native Windows/macOS lanes. Evidence references must be HTTPS URLs without URL userinfo or existing files (symlinks are followed) named by an absolute path or `./` path relative to the checkout. Paths may be outside the checkout; HTTPS query strings may contain credentials, so do not put secrets in evidence references. HTTPS reachability, report contents and reviewer identity are still out-of-band checks. The builder must use the same clean commit; the checker cannot prevent source edits after it returns.

The development notice set includes the exact pinned Node.js 22.23.4 source LICENSE and bundled-component notices, with checked-in source URL and SHA-256 provenance. The builder refuses a different runtime version or changed notice bytes. Version matching is not proof that a custom or vendor-patched Node executable has identical components or licensing; final runtime provenance and notice completeness still require review before distribution.

## Downloadable stable-release preparation (moved from README)


A separate [downloadable release policy](downloadable-beta-policy.md) defines
an unsigned executable candidate that does not bundle Chrome. It requires an interactive terminal on first
run and asks before downloading a fixed Chrome for Testing version directly from Google,
then retains it in a local cache. It needs internet for that first download and
is not an offline all-in-one bundle. Stable version `2026.11.16` was prepared without a prerelease suffix and is published as [v2026.11.16](https://github.com/404-Page-Found/EducationPerfected/releases/tag/v2026.11.16) (15 November 2026), with the five-target native validation, exact-artifact notices/integrity evidence and release approval completed for it. Existing development builds that embed Chrome are not eligible
for this publication path. Source ZIP use is unchanged: `npm ci`, then `npm run cli`.

## Packaged maintenance (moved from README)


Packaged maintenance: see [runtime storage and uninstall](runtime-storage.md). `uninstall` requires typed confirmation (each item defaults to keeping it) and removes the saved login, app data and downloaded browsers only where ownership is safe, then removes the program itself the way it was installed: the Windows setup exe runs its own uninstaller, npm runs `npm uninstall -g`, `.deb`/`.rpm` run the package manager with sudo, `.pkg` removes its files and forgets the installer receipt, and installer scripts delete what they wrote. Every installer records what it created in `educationperfected-install.json` next to the executable; installs without a record are detected from their location and reported as inferred. On Windows a background helper finishes program removal after the CLI exits (a running program cannot delete itself) and writes a log. Close all other copies, including source CLI, and their Chrome windows first. Live/uncertain data or download locks are retained and removal is reported incomplete. `update` uses published stable GitHub Releases with verified checksums, a local confirmation and backup/rollback. Checksums detect corruption, not a compromised publisher; publication stays owner-approved per release.
