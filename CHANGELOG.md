# Changelog

## Unreleased

- Support reports for unsupported-question refusals now say which guard fired: the foreign-controls branch is split per refusal site (`foreign-choice`, `foreign-multiselect`, `foreign-dropdown`, `foreign-textbox`, `foreign-formula`, `foreign-slide-surfaces`; the old `foreign-controls` stays for any other editable-controls refusal). A refusal site that carries no shape of its own now gets a read-only page probe (game mode, question type, component codes, visible control counts, no text), so the shape is no longer all unknown. Still schema 1. The relay must be redeployed with the new branch list before this build sends.

- A choice or multi-select slide refused for editable controls outside the choice component now records its content-free shape (game mode, question type, component codes, control counts) in the support report, and relay issues list the refusal branch on each shape line.

- Anonymous support reports for an unsupported question now carry its content-free shape (still schema 1; older builds' four-field reports stay valid), so an issue says what to build instead of only that something was refused: the refusal branch (assessment, Dash, unknown game mode, unreadable state, extra components, and so on), game mode, EP question type number, component codes (unlisted ones are redacted) and control counts. All values come from fixed lists or small integers; no question text, answers, URLs or identifiers. Other reports stay at four fields. The relay files one issue per refusal branch and lists the shapes it has seen. The local console diagnostic is unchanged and the report block now also prints the branch and components. The relay is redeployed with this change.

- Collapsing the desktop sidebar now keeps a 64px quick rail instead of only the expand button: a status dot with a short label (green running, amber while a change applies, red after an error, gray when idle or done), Stop (a blue Start when stopped) and Refresh words as icon buttons with tooltips, and the app logo with the version pinned at the bottom. The expand toggle stays at the top; collapsing is still session-only. Start and Refresh stay disabled once the browser session has closed, where they could not act, and Refresh words is now disabled during a run, which always rejected the action, and a rail action failure shows a small alert icon whose tooltip carries the message, since the pane's own message line hides when collapsed.

- Anonymous support reports are now on by default and go to the project's relay, which files one GitHub issue per task type and reason. Only task type, reason, app version and schema are sent (an unsupported-question refusal adds a content-free shape, see the entry above). Turn off with `reports off`, the desktop switch, `supportReports: false` or `EP_SUPPORT_REPORTS=off`.

- Anonymous support reports can now be turned on or off from the CLI (`reports`, `reports on`, `reports off`, when stopped) and from a desktop switch. The choice is saved as `supportReports` in `config.json`; `EP_SUPPORT_REPORTS=off` still wins. No relay is configured yet, so nothing is sent.

- Config schema is now numbered version 1 (was 2). Saved version 1 and version 2 files both load with their accuracy and pacing choices kept, retired keys still drop, and a version 2 file is overwritten once as version 1 with the same choices when it is loaded. Any other version is ignored.

- Browser accuracy and pacing now use on/off switches with immediate changes, confirmed-state sync and pending/running locks. Read buttons stay available. As with desktop settings, a storage-write failure keeps the session-only setting and terminal warning.
- The browser control panel defaults to the top right while preserving a saved position. In the desktop app it appears only when the sidebar is collapsed; CLI sessions keep it visible.

- Restrict floating browser-panel dragging, resize and saved positions to the page client area before the scrollbars, keeping the whole panel within the available height.

- Keep the desktop version strip flush with the bottom of the left pane for both short and scrollable content.

- Desktop accuracy and pacing now use labelled on/off switches instead of text boxes and Apply buttons. Switches reflect saved state, save immediately and lock while running or applying a change. Rejected setting actions restore the last reported state and show the error. Storage-write failures retain the existing session-only behavior with a terminal warning; the switches do not guarantee persistence if storage is unavailable.

- Information-slide Continue can prove advance to an unsupported renderer from a changed valid identity in the same visible lesson model. The next round still refuses unsafe questions, and an unchanged identity still stops without retry. Synthetic regression coverage only.

- Support explicitly self-marked Smart Lesson dropdowns as verified fill-only, stopping before submission or self-grading (#338). Synthetic coverage only; mixed or unknown marking remains refused.

- Mixed formula/plain single-choice options now stay on the exact cached-renderer association path instead of requiring formula syntax in every option. Plain alternatives need the supported literal/block grammar and matching current rendered text; stale, ambiguous or unsupported choices still stop unanswered. Source-derived fixtures only, not live account verification.

## v2026.11.16

First V2026 stable release. Full PR list: [v2.2.0...v2026.11.16](https://github.com/404-Page-Found/EducationPerfected/compare/v2.2.0...v2026.11.16).

- Support for multiple-choice questions, Smart Lesson choice and Listening/Dictation handlers, guarded multi-select choices, and guarded drag-and-drop fill-in-the-gaps.
- Guarded auto-marked textbox, block colour and one-question fill-only validation for Smart Lessons; Assessment and unknown contexts are refused before any input.
- Windows installer with a Start Menu entry, renamed to `educationperfected-windows-x64-setup.exe`; the command installs as `educationperfected.exe`.
- Unified uninstall: install records on every installer, with program removal on every install method.
- Publish workflow builds and attaches the verified bundle to draft releases.
- Documentation: README install, usage and dependency guidance refreshed; installers presented as the primary install method.

- npm registry publication: the `Publish` workflow now publishes the byte-verified npm package to the registry itself, as its last job and only once the GitHub release is live (the package's postinstall downloads the platform binary from the release). A version already on the registry is skipped, so re-runs are safe; credentials are the `NPM_TOKEN` secret, or OIDC trusted publishing once the `NPM_TRUSTED_PUBLISHING` repository variable is set after configuring it on npmjs.com (the first publish needs the token, because npmjs.com only offers trusted publishing for a package that already exists), and the job fails before publishing with the setup steps when neither exists. The npm install route is now the plain registry install, `npm install -g --allow-scripts=educationperfected educationperfected` - the `--allow-scripts` opt-in is required on npm 12+, which blocks install scripts by default. Downloading the release `.tgz` to install it with npm is gone from the docs (the tarball stays attached as the publish artifact).

- App icon: the project owner's E-and-check tile now brands the app. `branding/` keeps the source SVG plus derived PNG, `.ico` and `.icns` sets; the Windows executables embed the icon and a version identity at build time, and the Windows setup exe, its wizard, the Start Menu shortcuts and the Settings uninstall entry all show it. The macOS and Linux CLI packages carry no icon (bare CLI binaries have no standard icon slot); the `.icns` is ready for the desktop app.

- Unified uninstall: every installer now writes an install record (`educationperfected-install.json`) and `uninstall` removes the program itself on every install method, after the existing per-item data/login/browser prompts (each still defaults to No). Windows setup exe runs its own uninstaller; npm runs `npm uninstall -g`; `.deb`/`.rpm` run the package manager with sudo; `.pkg` removes its files and forgets the receipt; install.sh/install.ps1/raw binaries delete what they wrote, including the install.ps1 PATH entry. Windows program removal finishes in a detached background helper after the CLI exits (a running program cannot delete itself) and writes a log to `%TEMP%\educationperfected-uninstall.log`. Installs without a record are detected from their location and reported as inferred. Per-OS removal paths are code-reviewed and synthetically tested but not yet verified on real machines of every platform.
