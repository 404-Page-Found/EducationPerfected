# Changelog

## Unreleased

- Reflection/self-mark support (#114): the normal CLI can fill one empty, source-associated long-answer editor with the user's own single-line response, after displaying it and receiving a separate typed `yes`. No placeholder or model answer is used. Both modes stop after verified fill, leaving Submit, warning dialogs, self-marking and Next to the user. Existing work, mixed editors, modals, stale state and Assessments refuse without retry. Source-derived synthetic handler/CLI coverage only; no live Reflection answer has been filled or submitted.

- Dropdown + number-box/textbox mixed slides: a Smart Lesson slide combining dropdown questions with number-box and/or text-box inputs (identified from live refusal diagnostic pastes: four dropdowns and six number boxes, then two dropdowns, six number boxes and one text box, every definition authored-unmarked) is now answered instead of refused. Every surface present must meet its established contract in full, composed all-or-nothing, with uniform marking across every definition; answers still come only from EP's own accepted answers (dropdown Correct flags, number-box and text-box answer options), input is the F4-popup dropdown flow followed by per-character typing with re-verification around every input, then one Submit. Anything outside the contract still refuses content-free with zero key input and zero Submits, and single-surface slides are unchanged. Synthetic fixture coverage only.

- Terminal Submit approvals removed: auto mode no longer pauses for a typed `yes` before the one guarded Submit on dropdown, number-box, textbox or mixed dropdown+number-box/textbox questions - the user defines every typed-yes-before-Submit step as live-proven. Every refusal, stop-instead-of-guessing guard, the submit-readiness wait, the Assessment boundary and semi-auto fill-only behavior are unchanged; the Reflection self-mark path still asks for typed confirmation because it fills the user's own response and never submits.

- Dropdown mixed-slide layout diagnostics: a dropdown slide refused for extra editable controls (`mixed-editable-inputs`) now also reports each extra control's fixed-shape layout hooks (`answerBox` when it carries EP's text-box or number-box class, `inGapsComponent` when it sits inside the fill-in-the-gaps wrapper), whether the dropdowns themselves are gap-wrapped (`selectsInGaps`), and a content-free `definitions` summary (total, per-type counts under fixed component-type names, marking tallies). No values, labels, ids, raw class strings or answers are included, and the slide stays refused; the layout facts identify which answer surfaces share the slide so mixed answering can be designed or the refusal confirmed. Synthetic fixture coverage only.

- Dropdown mixed-slide refusal diagnostics: a dropdown slide refused for extra editable controls (`mixed-editable-inputs`) now names those controls in the printed diagnostic - each extra control's tag, an allowlisted HTML input type, and its content-editable/disabled/read-only flags, with a count and an 8-entry cap. No page text, answers, ids or classes are included, and the slide stays refused; the named controls tell us which non-dropdown element stopped the run so the shape can be mapped. Synthetic fixture coverage only.

- Smart Lesson highlight questions: click-the-correct-tokens slides (`HIGHLIGHT_COMPONENT`) in explicitly auto-marked Smart Lessons are now answered under a narrow source-derived contract. The answer comes from the correct token indexes EP ships to the client; the handler clicks each correct token once with a full identity and selection re-check around every input, submits once in auto mode, and leaves submission to the user in semi-auto mode. It stops instead of guessing on anything outside the contract (mixed slides, stored selections, malformed marking or token metadata, single-answer slides with multiple correct tokens). Synthetic fixture coverage only; no live highlight slide has been captured or answered yet.

- Browser download progress: the first-run Chrome download now shows a progress bar with percent and MB downloaded. On a terminal the bar updates in place; in logs or pipes it prints a line every 10%.

- npm registry publication: the `Publish` workflow now publishes the byte-verified npm package to the registry itself, as its last job and only once the GitHub release is live (the package's postinstall downloads the platform binary from the release). A version already on the registry is skipped, so re-runs are safe; credentials are the `NPM_TOKEN` secret, or OIDC trusted publishing once the `NPM_TRUSTED_PUBLISHING` repository variable is set after configuring it on npmjs.com (the first publish needs the token, because npmjs.com only offers trusted publishing for a package that already exists), and the job fails before publishing with the setup steps when neither exists. The npm install route is now the plain registry install, `npm install -g --allow-scripts=educationperfected educationperfected` - the `--allow-scripts` opt-in is required on npm 12+, which blocks install scripts by default. Downloading the release `.tgz` to install it with npm is gone from the docs (the tarball stays attached as the publish artifact).

- App icon: the project owner's E-and-check tile now brands the app. `branding/` keeps the source SVG plus derived PNG, `.ico` and `.icns` sets; the Windows executables embed the icon and a version identity at build time, and the Windows setup exe, its wizard, the Start Menu shortcuts and the Settings uninstall entry all show it. The macOS and Linux CLI packages carry no icon (bare CLI binaries have no standard icon slot); the `.icns` is ready for the desktop app.
- Unified uninstall: every installer now writes an install record (`educationperfected-install.json`) and `uninstall` removes the program itself on every install method, after the existing per-item data/login/browser prompts (each still defaults to No). Windows setup exe runs its own uninstaller; npm runs `npm uninstall -g`; `.deb`/`.rpm` run the package manager with sudo; `.pkg` removes its files and forgets the receipt; install.sh/install.ps1/raw binaries delete what they wrote, including the install.ps1 PATH entry. Windows program removal finishes in a detached background helper after the CLI exits (a running program cannot delete itself) and writes a log to `%TEMP%\educationperfected-uninstall.log`. Installs without a record are detected from their location and reported as inferred. Per-OS removal paths are code-reviewed and synthetically tested but not yet verified on real machines of every platform.
